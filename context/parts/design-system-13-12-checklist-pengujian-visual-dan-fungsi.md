## 12. Checklist Pengujian Visual dan Fungsional

### Konsistensi UI

-   [ ] Semua layar menggunakan light theme yang sama.
-   [ ] Warna, tipografi, spacing, radius, dan ukuran kontrol berasal
    dari tokens.
-   [ ] Tombol utama, sekunder, dan destruktif terlihat berbeda.
-   [ ] Status memiliki label teks dan warna yang konsisten.
-   [ ] Komponen Tambah dan Edit menggunakan pola visual yang sama.

### Responsivitas

-   [ ] Tidak ada overflow horizontal pada lebar 320--360 dp.
-   [ ] Tampilan diuji pada ukuran ponsel kecil, normal, dan besar.
-   [ ] Layar diuji pada perangkat dengan notch/punch-hole kamera.
-   [ ] Konten tidak tertutup status bar atau navigation bar.
-   [ ] Form tetap dapat di-scroll ketika keyboard terbuka.
-   [ ] Dialog tetap muat pada layar kecil dan font besar.
-   [ ] Layout tetap masuk akal pada landscape dan tablet/foldable.

### Fungsionalitas

-   [ ] Daftar tugas berasal dari penyimpanan lokal.
-   [ ] Tambah tugas menyimpan semua field yang diisi.
-   [ ] Detail menampilkan data yang tepat.
-   [ ] Edit mempertahankan nilai awal dan menyimpan perubahan.
-   [ ] Hapus meminta konfirmasi.
-   [ ] Status dapat diubah dan perubahan terlihat pada daftar.
-   [ ] Data tetap ada setelah aplikasi ditutup dan dibuka kembali.
-   [ ] Operasi dasar tetap berjalan tanpa internet.
-   [ ] UI tidak mengakses database secara langsung.
-   [ ] Error tidak menyebabkan input pengguna hilang.

### Bukti praktikum

-   [ ] Screenshot layar Daftar Tugas.
-   [ ] Screenshot layar Tambah Tugas.
-   [ ] Screenshot layar Detail Tugas.
-   [ ] Screenshot layar Edit Tugas.
-   [ ] Screenshot bukti data tetap tersedia setelah aplikasi dibuka
    kembali/offline.
-   [ ] Repository Git memiliki minimal lima commit bermakna.
-   [ ] README menjelaskan fitur dan cara menjalankan.
-   [ ] PDF laporan memuat screenshot, penjelasan singkat, dan jawaban
    pertanyaan demo.
-   [ ] Video demo berdurasi 3--5 menit atau siap melakukan demo
    langsung.
